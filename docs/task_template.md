# [기능명] 구현 작업 계획

## 1. 작업 개요

- 요구사항 문서: `requirements.md`
- 기술 설계 문서: `design.md`
- 목표: [이번 구현을 통해 달성할 결과]
- 작업 범위: [구현 대상]
- 제외 범위: [이번 구현에서 다루지 않는 사항]

## 2. Task 목록

| ID   | Task     | 선행 작업 | 상태 |
| ---- | -------- | --------- | ---- |
| T-01 | [작업명] | 없음      | TODO |
| T-02 | [작업명] | T-01      | TODO |
| T-03 | [작업명] | T-02      | TODO |

상태는 다음 네 가지를 사용한다.

- `TODO`: 아직 시작하지 않음
- `IN_PROGRESS`: 구현 또는 검증 진행 중
- `BLOCKED`: 의존성이나 미해결 문제로 중단됨
- `DONE`: 완료 조건 및 검증 통과

## 3. 상세 Task

### T-01. [Task 제목]

**상태:** TODO

**목표**

이 Task를 완료했을 때 달성해야 하는 결과를 작성한다.

**관련 요구사항 및 설계**

- 요구사항: [관련 요구사항]
- 설계: [관련 설계 섹션]

**선행 작업**

- 없음

**작업 내용**

- [ ] 구현 작업 1
- [ ] 구현 작업 2
- [ ] 구현 작업 3

**예상 변경 범위**

- Backend: [관련 모듈이나 파일]
- Frontend: [관련 모듈이나 파일]
- Database: [변경 사항]
- 기타: [설정 또는 인프라]

실제 코드 분석 전에는 파일 경로를 추측하지 않는다.

**완료 조건 (Acceptance Criteria)**

- [ ] 검증 가능한 조건 1
- [ ] 검증 가능한 조건 2
- [ ] 검증 가능한 조건 3

**검증 방법**

- [ ] 단위 테스트
- [ ] 통합 테스트 또는 수동 시나리오 검증
- [ ] 기존 기능 회귀 확인

해당 Task와 무관한 검증 항목은 제외하고 실제 검증 명령이나 시나리오를 기록한다.

**실행 결과**

- 변경 내용: 미작성
- 검증 결과: 미실행
- 남은 문제: 없음

## 4. 전체 완료 기준

- [ ] 모든 필수 Task가 DONE 상태다.
- [ ] 요구사항의 완료 및 검증 기준을 충족한다.
- [ ] 관련 테스트가 통과한다.
- [ ] 기존 기능에 대한 회귀 검증을 완료했다.
- [ ] 미해결 문제와 후속 작업을 기록했다.
