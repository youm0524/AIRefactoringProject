- 상태: 진행 중 — API·탭 연결 완료, 목록 렌더링 전 사용자 확인 대기

## 1. 목표와 범위

자기소개서 탭에서 로그인 사용자의 초안을 리스트로 조회·선택·삭제할 수 있게 한다. 상세 선택 시 초안 ID를 전달할 이동 구조까지 준비한다. 실제 상세 로딩·작성·저장과 공고에서 최초 생성하는 연결은 8단계에서 완성한다.

## 2. 화면 구성

| 영역·상태 | 표시 및 동작 |
| --- | --- |
| 목록 | ‘내 자기소개서’ 제목, 기업명·공고명·최종 수정 시각, ‘이어서 작성’·‘삭제’ 버튼 |
| 페이지 이동 | 기본 20개, 최근 수정 순. 이전·다음 버튼과 현재 페이지 표시 |
| 로그인 전 | 로그인 안내와 버튼. 로그인 후 본인 목록 조회 |
| 로딩·조회 실패 | 로딩 안내 또는 오류·재시도. 실패를 빈 목록으로 표시하지 않음 |
| 빈 목록 | ‘저장한 자기소개서가 없습니다’와 ‘채용공고 찾기’ 버튼 |
| 삭제 | 확인 창 → 삭제 요청 → 성공 후 목록 재조회. 취소하면 요청하지 않음 |

수정 시각은 한국 시간으로 표시한다. 일반 목록에는 별도 신규 작성 버튼을 두지 않고, 작은 화면에서는 한 열로 배치한다.

## 3. 추가·수정할 파일

경로는 `frontend/` 기준이다. 기존 React 상태 전환·Fetch·CSS 구성을 유지한다.

| 대상 | 작업 |
| --- | --- |
| `src/pages/CoverLetterListPage.jsx` | 목록 조회·페이지·로그인 안내·삭제 처리 |
| `src/app/App.jsx` | 상단·하단 탭을 목록에 연결, 선택 초안 ID·인증·이동 이벤트 전달 |
| `src/shared/api/careerpickApi.js` | 목록·삭제 함수, 오류 상태·코드·메시지와 응답 본문 없는 `204` 처리 |
| `src/app/App.css` | 리스트·상태 안내·반응형 스타일 |
| `test/` | API 응답·오류·삭제 처리의 테스트 |
| `FRONTEND.md` | 새 화면·API·상태 흐름 안내 |

## 4. 작업 순서

- [x] **API 연결:** `getCoverLetters`와 `deleteCoverLetter`를 추가한다. 인증 헤더를 사용하고 기존 공고·로그인·채팅 호출과 호환성을 유지한다.
- [x] **탭 연결:** 상단·하단 자기소개서 탭에서 목록을 열고, ‘이어서 작성’은 공고 ID가 아닌 초안 ID를 전달한다. 서버 초안을 기존 로컬 초안 편집기로 연결하지 않는다.
- [ ] **목록 렌더링:** `items`와 페이지 정보를 사용한다. 로그인 확인 중·로딩·빈 목록·실패 상태를 구분한다.
- [ ] **페이지 처리:** 페이지 변경 시 재조회한다. 마지막 페이지의 마지막 항목을 삭제하면 유효한 이전 페이지로 이동한다.
- [ ] **삭제 처리:** 확인 후 호출하고 중복 요청을 막는다. 실패하면 항목을 유지하며 재시도를 안내한다. 이미 삭제된 대상의 `404`는 안내 후 목록을 갱신한다.
- [ ] **인증·요청 정리:** `401`은 재로그인으로 연결한다. 로그아웃·계정 전환 시 목록·선택 ID를 비우고, 이전 요청의 늦은 응답이 새 화면을 덮어쓰지 않게 한다.
- [ ] **검증·문서 갱신:** 아래 항목을 확인하고 완료 결과를 기록한다.

## 5. 검증 및 완료 기준

- 상단·하단 탭에서 동일한 리스트가 열리고, 실제 API의 기업명·공고명·수정 시각이 표시된다.
- 이전·다음 페이지, 빈 목록, 서버 오류·재시도, 로그인 전·세션 만료 상태가 구분된다.
- 삭제 취소 시 요청이 없고, 성공 시 목록 갱신·마지막 페이지 보정이 된다. `204`를 JSON 파싱 실패로 처리하지 않는다.
- 로그아웃·계정 전환·빠른 페이지 변경 시 다른 사용자 또는 이전 페이지의 응답이 표시되지 않는다.
- 선택한 초안 ID가 상세 이동 상태에 전달된다. 실제 상세 편집까지의 검증은 8단계에서 수행한다.
- `npm test`, `npm run build` 및 브라우저에서 목록·삭제·로그인·작은 화면 동작을 확인한다. 기존 공고·로그인·채팅도 변경 영향 범위에서 검증한다.

## 6. 항목별 진행 결과

- API 연결 완료: `getCoverLetters(token, page, size, {signal})`, `deleteCoverLetter(coverLetterId, token, {signal})` 추가.
- 오류의 `status`·`code`·`message`를 보존하고, 삭제 성공의 `204`는 JSON 파싱 없이 처리한다. 기존 API의 성공 반환 형식은 유지한다.
- Fetch 모의 응답 기반 테스트 포함 총 8개와 빌드 통과. 수정한 API 파일의 ESLint 검사 통과.
- 전체 ESLint는 기존 JSX 파일의 줄바꿈 규칙 위반 259건으로 실패했다. 해당 파일들은 이번 항목에서 수정하지 않았다.
- 탭 연결 완료: 상단·하단 버튼은 공통 `openCoverList`로 목록 화면을 연다. 목록·서버 상세·기존 로컬 작성 경로를 분리했다.
- `selectedCoverLetterId`와 `openCoverDetail`을 준비해 목록의 `onOpen`에 연결했다. 항목 버튼과 데이터 표시가 아직 없어 실제 선택·상세 로딩 검증은 후속 항목에서 수행한다.
- 목록·상세 화면은 제목·이동 골격만 추가했다. 공고의 기존 로컬 작성 흐름은 8단계 전까지 유지한다.
- 탭 연결 후 빌드·새 목록 파일 ESLint 통과. 기존 프론트엔드 테스트 8개도 통과했다. 브라우저 동작 검증은 아직 수행하지 않았다.
- 다음 ‘목록 렌더링’은 사용자 확인 후 시작한다.
