## 3. 현재 동작

- 상단·하단 자기소개서 버튼은 공고 없는 자유 작성 화면을 연다.
- 공고 상세에서 작성을 누르면 해당 공고의 작성 화면을 연다. 나가기 버튼은 채용공고 화면으로 돌아간다.
- 지원 동기·직무 경험 두 문항이 고정되어 있고, 각각 700자까지 입력할 수 있다.
- 저장 버튼을 누르면 공고 ID별로 `localStorage`에 저장하며, 같은 화면을 다시 열 때 불러온다. 자유 초안은 `general` 키를 사용한다.
- 저장한 초안 목록과 자기소개서 서버 API·테이블은 없다.
- 자기소개서 작성·저장은 로그인 없이 가능하고, 로컬 초안은 사용자별로 구분되지 않는다.
- 서버 인증은 Bearer 토큰과 Redis 세션으로 사용자를 확인한다. 위 내용은 코드 확인 결과이며 화면 실행 검증은 아직 하지 않았다.

## 4. 결정할 사항

사용자가 결정 결과에 작성한 내용을 기준으로 추천안 적용을 확정한다. 기업별 문항 제공은 후속 확장으로 기록한다.

| 항목 | 현재 동작 | 추천안 | 결정 결과 |
| --- | --- | --- | --- |
| 화면 이동 | 탭 → 자유 작성, 나가기 → 공고 | 탭 → 목록 → 상세, 상세에서 목록 복귀 | 추천안 적용 |
| 최초 생성 | 서버 생성 없음 | 공고에서 작성 시작 시 생성, 기존 초안이 있으면 열기 | 추천안 적용 |
| 로그인 | 작성·저장에 불필요 | 목록·조회·저장 모두 로그인 필수 | 추천안 적용 |
| 초안 개수 | 브라우저에서 공고별 1개 | 사용자·공고별 1개 | 추천안 적용 |
| 자유 초안 | 공고 없이 작성 가능 | 이번 구현은 공고 연결 초안으로 한정 | 추천안 적용 |
| 기존 로컬 초안 | 브라우저에만 보관 | 원본 보존, 자동 이전 없이 서버 초안과 분리 | 추천안 적용 |
| 문항 | 고정 2개, 각 700자 | 기존 문항·제한 유지, 문항 편집은 범위 제외 | 문항도 이제 기업별로 제공하는 걸 api로 받아오는 것처럼 만들고 싶은데, 우선은 추천안으로 적용  |

### 확정한 작업 범위

- 포함: 로그인 사용자별 목록·상세·저장·삭제, 공고에서 최초 생성 또는 기존 초안 열기, 사용자·공고별 초안 1개, 상세에서 목록 복귀.
- 문항: 이번에는 기존 두 문항과 각 700자 제한을 유지한다. 질문과 답변을 상세 API로 전달하는 구체적인 구조는 3단계에서 정한다.
- 제외: 공고 없는 자유 초안 작성, 문항 편집, 기존 로컬 초안 자동 이전. 로컬 원본은 삭제하지 않고 서버 초안과 분리한다.
- 후속 확장: 기업별로 제공하는 문항을 API로 받아오는 기능. 이번에는 기존 문항을 유지하되 3단계 데이터·API 설계에서 확장 방향을 검토한다.
