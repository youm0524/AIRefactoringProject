# Issue #7 — 2단계: 화면 구성 정하기

- 전체 계획: [Issue-#7-Feature.md](Issue-%237-Feature.md)
- 선행 결정: [1단계 문서](Issue-%237-Feature-Step-1.md)
- 상태: 완료 — 화면 구성 확정, 3단계 데이터·API 설계 진행 가능

## 1. 작업 목표

목록·상세 화면에서 보여줄 정보와 이동·저장 동작을 정한다. 이번 단계는 화면 구성 결정까지 진행하며, 실제 UI 구현은 7·8단계에서 수행한다.

## 2. 이미 확정한 기준

- 로그인 사용자만 목록·상세·저장을 이용하며, 사용자·공고별 초안은 1개다.
- 자기소개서 탭은 목록을 열고, 항목 선택 시 상세로 이동한다. 상세에서는 목록으로 돌아간다.
- 공고에서 작성 시작 시 초안을 생성하고, 기존 초안이 있으면 해당 상세를 연다.
- 공고 없는 자유 작성은 제공하지 않는다. 기존 로컬 초안은 보존하되 서버 초안과 분리한다.
- 기존 두 문항과 각 700자 제한을 유지한다. 기업별 문항 제공은 후속 확장이다.

## 3. 확정한 화면 구성

| 화면 | 위에서 아래로 표시할 내용 |
| --- | --- |
| 목록 | ‘내 자기소개서’ 제목 → 저장한 초안의 리스트형 목록 |
| 목록 항목 | 기업명, 공고명, 최종 수정 시각, ‘이어서 작성’·‘삭제’ 버튼 |
| 상세 | ‘목록으로’ 버튼 → 기업명·공고명 → 문항별 질문·답변·글자 수 → ‘초안 저장’ 버튼 |

이동 흐름: `자기소개서 탭 → 목록 → 상세 → 목록`. 신규 작성은 `채용공고 상세 → 작성 시작 → 생성 또는 기존 초안 상세`로 연결한다.

## 4. 결정할 사항

사용자가 작성한 결정 결과를 기준으로 아래 화면 동작을 확정한다.

| 항목 | 추천안 | 결정 결과 |
| --- | --- | --- |
| 목록 표현 | 카드형 목록에 기업명·공고명·최종 수정 시각·이어서 작성 버튼 표시 | 리스트형 목록, 구성요소는 추천안 적용 |
| 목록 정렬 | 최근 수정한 초안부터 표시 | 추천안 적용 |
| 신규 작성 진입 | ‘채용공고'에서 공고 선택으로 공고 화면 이동 후 작성 시작 | 추천안 적용 |
| 로그인 전 진입 | 로그인 안내와 버튼 표시, 공고에서 시작했다면 로그인 후 해당 공고 작성 계속 | 추천안 적용 |
| 저장 성공 | 상세 화면 유지, 성공 알림과 마지막 저장 시각 갱신 | 추천안 적용 |
| 미저장 상태에서 이동 | 목록·다른 탭으로 이동하기 전 변경사항을 버릴지 확인 | 추천안 적용 |
| 작은 화면 | 목록과 문항을 세로 한 열로 배치 | 추천안 적용 |

삭제 추가 결정: 목록에서 삭제 확인 창을 열고, 확인한 경우에만 초안과 문항·답변을 함께 삭제한다. 성공 후 목록을 갱신하며 같은 공고에서 다시 작성하면 새 초안을 만든다.

## 5. 상태별 표시

- 로딩: 불러오는 중 안내. 최초 생성·저장 요청 중에는 해당 버튼의 중복 클릭을 막는다.
- 빈 목록: ‘저장한 자기소개서가 없습니다’와 ‘채용공고 찾기’ 버튼을 표시한다.
- 조회 실패: 오류 안내와 재시도 버튼을 표시한다. 빈 목록으로 처리하지 않는다.
- 상세 없음: 대상을 찾을 수 없다는 안내와 목록 이동 버튼을 표시한다.
- 삭제: 요청 중 중복 클릭을 막고, 실패 시 항목을 유지하며 오류·재시도를 안내한다. 마지막 페이지가 비면 이전 페이지를 조회한다.
- 저장 실패: 작성 내용을 유지하고 실패 안내·재시도를 제공한다.
- 로그인 만료: 재로그인을 안내하고, 같은 사용자로 복귀하면 작성 내용을 이어갈 수 있게 한다. 다른 계정에는 이전 내용을 표시하지 않는다.

## 6. 작업 체크리스트 및 완료 기준

- [x] 1단계 결정에 맞춰 목록·상세 구성과 이동 흐름을 제안한다.
- [x] 4번 표의 화면 동작과 5번 상태별 표시안을 검토하고 확정한다.
- [x] 확정한 화면에 필요한 정보를 아래에 정리해 3단계 설계 기준으로 기록한다.

화면 구성과 주요 상태의 동작이 확정되면 완료한다. API 필드·경로와 목록 페이지 처리 방식은 3단계에서 구체화한다.

## 7. 3단계 설계에 반영할 내용

- 목록: 초안 식별자, 기업명, 공고명, 최종 수정 시각을 제공하고 최근 수정 순으로 조회한다.
- 상세: 연결 공고 정보, 문항별 식별자·질문·답변·글자 제한, 마지막 저장 시각을 제공한다.
- 삭제: 본인 초안만 삭제하고 성공 후 목록을 갱신한다.
- 생성: 선택한 공고로 신규 초안을 만들거나 기존 초안을 반환한다.
- 저장·인증: 성공 후 갱신 시각을 반영하고, 인증 만료·대상 없음·저장 실패를 구분한다. 재로그인 시 같은 사용자인지 확인할 방법도 정한다.
- 신규 작성은 채용공고에서 시작한다. 일반 목록에는 별도 작성 버튼을 두지 않고, 빈 목록에는 5번의 ‘채용공고 찾기’ 안내를 유지한다.
