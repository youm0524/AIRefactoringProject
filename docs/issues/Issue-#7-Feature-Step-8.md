## 1. 목표와 범위

공고에서 작성을 시작하고, 서버 문항·답변을 불러와 수정·저장한 뒤 목록에서 다시 열 수 있게 한다. 현재 로컬 저장 방식의 작성 화면을 서버 기반으로 전환하되 기존 로컬 초안은 삭제·자동 이전하지 않는다.

## 2. 연결할 API와 화면 동작

| 동작 | API·결과 |
| --- | --- |
| 공고에서 작성 시작 | `POST /api/cover-letters`, `{jobId}` → 신규 또는 기존 초안의 상세로 이동 |
| 목록에서 이어서 작성 | `GET /api/cover-letters/{coverLetterId}` → 저장된 문항·답변 표시 |
| 초안 저장 | `PUT /api/cover-letters/{coverLetterId}`, `{items: [{id, answer}, ...]}` → 저장된 상세 반영 |
| 목록으로 복귀 | 목록을 재조회해 답변 저장의 수정 시각과 정렬 반영 |

- 상세는 ‘목록으로’ → 기업명·공고명 → 질문·답변·글자 수 → 마지막 저장 시각·저장 버튼으로 구성한다.
- 질문·표시 순서·글자 제한은 상세 응답에서 읽는다. 이번에는 기존 두 문항·각 700자를 유지한다.
- 비로그인이면 로그인 후 선택한 공고의 작성을 이어간다. 생성 중 중복 클릭을 막고, 실패하면 오류·재시도를 제공한다.
- 상세 로딩·대상 없음·조회 실패를 구분한다. 존재하지 않는 공고·서버 장애를 로컬 저장 성공으로 대체하지 않는다.
- 저장 중에는 입력·중복 저장을 잠근다. 성공 응답 후에만 저장 완료를 표시하고, 실패 시 작성값을 유지한다.

## 4. 작업 순서

각 항목은 구현·검증 후 사용자 확인을 받고 다음 항목으로 넘어간다.

- [x] **API 연결:** 생성·상세·저장 함수를 추가한다. 경로에는 초안 ID, 답변에는 문항 ID를 사용한다.
- [x] **공고에서 작성 시작:** 로그인 확인 → 필요 시 로그인 후 재개 → 초안 생성 또는 기존 초안 반환 → 상세 이동을 연결한다. 기존 자유 작성·로컬 저장 진입을 제거한다.
- [x] **상세 조회·렌더링:** 선택 초안 ID로 문항·답변을 읽고 응답 순서로 표시한다. 다른 초안·계정으로 전환한 뒤 도착한 이전 응답을 제외한다.
- [x] **답변 편집·저장:** 문항별 입력·UTF-16 글자 수·길이 제한을 적용하고 모든 문항을 한 번에 저장한다. 빈 답변·공백을 보존하고 저장 실패 시 입력을 유지한다.
- [x] **목록 복귀·미저장 이탈:** 마지막 저장값과 현재 입력을 비교한다. 목록·다른 탭·다른 공고 이동 전 변경사항 폐기 여부를 확인하고, 목록 복귀 시 재조회한다. 확인 취소 시 현재 입력·화면을 유지한다.
- [x] **세션 만료·계정 전환:** 만료된 편집값은 초안 ID·원래 사용자 ID와 함께 메모리에 보관하고 재로그인한다. 같은 사용자만 복구하며 다른 계정·명시적 로그아웃에서는 제거한다. Step 7의 즉시 목록 복귀 처리를 보완하고, 만료 복구값을 로컬 초안에 자동 기록하지 않는다.
- [x] **검증·문서 갱신:** 자동 테스트·빌드·변경 파일 lint와 실제 화면을 확인하고 결과·남은 사항을 기록한다. 브라우저 닫기 경고·자동 저장은 이번 범위에 추가하지 않는다.

## 5. 검증 및 완료 기준

- 서로 다른 공고의 초안을 만들고 각각 저장·목록 복귀·다시 열었을 때 답변이 유지된다.
- 같은 공고는 기존 초안을 열고, 삭제 후 다시 작성하면 새 초안을 생성해 서버 목록에 나타난다.
- 저장 실패·미저장 이탈 취소에서는 입력이 보존되고, 저장 성공 후에는 불필요한 이탈 확인이 없다.
- 세션 만료 후 같은 사용자로 복귀하면 편집을 이어가며, 다른 사용자에게 기존 답변이 표시·저장되지 않는다.
- 조회 중 빠른 이동·중복 클릭·401·404·서버 장애·모바일·키보드 조작을 확인한다. 기존 목록·삭제·공고·로그인·채팅도 회귀 확인한다.

## 6. 항목별 진행 결과

- API 연결 완료: `createCoverLetter(jobId, token, {signal})`, `getCoverLetter(coverLetterId, token, {signal})`, `updateCoverLetter(coverLetterId, items, token, {signal})` 추가.
- 인증 헤더·JSON 요청·취소 신호를 지원하고 공통 오류 처리를 재사용한다. 공고 ID·초안 ID·문항 ID를 구분하며 빈 답변과 공백을 보존한다.
- Fetch 모의 응답으로 신규 201·기존 200, 상세·저장 응답, 오류·네트워크 실패·취소를 검증했다. 전체 테스트 30개·빌드·수정 API 파일 ESLint 통과.
- 공고 작성 진입 완료: 공고 버튼 → 인증 확인 → 서버 POST → 응답의 초안 ID로 상세 이동을 연결했다. 생성 중 진입 잠금·로딩·실패 재시도를 제공한다.
- 비로그인 시 선택한 공고를 기억해 로그인 성공 후 재개한다. 로그인 창 닫기·목록/공고 이동·로그아웃에서는 대기를 취소한다. 생성 중 401은 재로그인 후 같은 공고로 재개한다.
- 기존 로컬 편집기 진입을 제거했다. 로컬 원본은 삭제·자동 이전하지 않는다. 상세 화면은 아직 제목·목록 복귀만 표시하며 문항·답변 표시는 다음 항목이다.
- 진입 화면의 로그인·인증 확인·생성 중·인증 서버 장애 렌더링 검증을 추가했다. 테스트 총 33개·빌드·신규 화면 ESLint 통과. 실제 브라우저 생성·로그인 후 재개는 아직 검증하지 않았다.
- 상세 조회·렌더링 완료: 생성·목록 선택으로 받은 초안 ID로 GET 상세를 호출하고 기업명·공고명·문항·저장 답변·글자 제한·한국 시간의 마지막 저장 시각을 표시한다.
- 기존 고정 문항·로컬 읽기/저장 코드를 서버 조회로 교체했다. 로컬 원본은 건드리지 않으며 현재 답변은 읽기 전용이다. 편집·저장 버튼은 다음 항목에서 연결한다.
- 로딩·로그인 확인·401 재로그인·404 대상 없음·조회 오류와 재시도를 구분한다. 초안·계정·화면 변경 시 요청을 취소하고 현재 초안·사용자·토큰과 일치하는 응답만 표시한다.
- 문항 순서·서버 질문/제한·빈 답변/공백·UTF-16 글자 수·읽기 전용·한국 시간과 상태 표시를 검증했다. 테스트 총 37개·빌드·상세 화면 및 App.jsx ESLint 통과. 실제 브라우저 상세 조회는 아직 검증하지 않았다.
- 답변 편집·저장 완료: 서버 문항 ID별로 편집값을 관리하고 UTF-16 글자 수·최대 길이를 적용한다. 전체 문항의 `{id, answer}`를 PUT으로 보내며 빈 답변·공백을 보존한다.
- 저장 요청 중 입력·저장·상세의 목록 복귀 버튼을 잠근다. 성공 응답으로 답변과 마지막 저장 시각을 갱신하고, 실패 시 편집값·이전 저장 시각을 유지하며 재시도를 제공한다.
- 상세 이탈·계정 변경 시 진행 중 저장의 응답 반영을 중단한다. 401 저장 실패 시에는 편집값을 유지하고 로그인 안내를 표시한다. 재로그인 이후 입력 복구는 뒤의 세션 만료 항목에서 완성한다.
- 전체 답변·길이 경계·이모지·빈 값/공백·원본 보존·저장 중 잠금·성공/실패 UI를 검증했다. 테스트 총 42개·빌드·변경 소스 ESLint 통과. 실제 브라우저 저장·재조회는 아직 검증하지 않았다.
- 목록 복귀·미저장 이탈 완료: 마지막 조회/저장 응답과 현재 답변을 정확히 비교한다. 원래 값으로 되돌리거나 저장 성공 응답을 반영하면 확인 창을 띄우지 않는다. 공백·줄바꿈도 변경으로 판정한다.
- 상세의 목록 복귀, 상단/하단 탭·브랜드·커뮤니티·다른 공고 진입·명시적 로그아웃에 공통 이탈 검사를 적용했다. 취소 시 목적지 상태·입력·화면을 유지하고, 저장 중에는 이동을 막는다.
- 확인 후 목록으로 돌아가면 목록 화면이 다시 마운트되어 서버 목록·수정 시각·정렬을 재조회한다. 새로고침·브라우저 닫기 경고는 이번 범위에 추가하지 않았다.
- 변경·되돌림·폐기 확인/취소·저장 중 차단·저장 성공/실패 기준과 미저장 안내를 검증했다. 테스트 총 49개·빌드·변경 소스 ESLint 통과. 실제 브라우저 이탈 확인 창은 아직 검증하지 않았다.
- 세션 만료·계정 전환 완료: 상세 편집값을 초안 ID·원래 사용자 ID와 함께 App 메모리에 보관한다. 저장 PUT의 401도 공통 만료 처리로 연결하고, 같은 사용자로 재로그인하면 상세 GET 후 문항 ID에 맞춰 입력을 복구한다.
- 다른 사용자 로그인·명시적 로그아웃·목록/공고 이동 시 복구값을 제거한다. 로그인 창만 닫으면 메모리에 유지하며 다시 로그인할 수 있다. 복구 답변을 서버나 기존 로컬 초안에 자동 저장하지 않으며 새로고침 시 메모리와 함께 사라진다.
- 복구 후에도 서버 답변을 마지막 저장 기준으로 사용해 미저장 이탈 확인을 유지한다. 재조회에서 사라진 문항은 제외하고 새 문항은 서버 값을 사용한다. 변경된 길이 제한을 넘는 복구 답변은 잘라내지 않고 저장 시 검증한다.
- 동일 사용자·초안 복구, 다른 사용자·초안 차단, 빈 값·공백·줄바꿈·이모지 보존, 문항 변경과 길이 제한 변경을 검증했다. 전체 테스트 52개·빌드·변경 소스 ESLint 통과. 실제 브라우저의 만료→재로그인·계정 전환은 아직 검증하지 않았다.
- 최종 검증 착수: 자동 검사·문서 갱신을 마쳤다. 실제 화면 검증은 브라우저 도구 연결 오류로 남아 있으며 아래 7절에 구분해 기록한다.

2026-11-02 이어서 검증 재시도: 브라우저 스킬의 공식 초기화 경로로 다시 연결했으나 `Importing module "node:process" is not allowed in node_repl` 오류가 재발했다. 초기화 후 `agent`도 생성되지 않아 브라우저 선택·문제 해결 문서 조회·화면 조작을 진행할 수 없었다. 실제 화면 검증 결과와 아래 체크리스트는 변경하지 않았다.

2026-11-02 추가 재시도: 새 요청에서 공식 초기화를 다시 실행했으나 동일한 `node:process` 모듈 허용 오류로 중단됐다. 브라우저 화면에 접근하지 못했으며 Step 8의 실제 화면 검증은 여전히 미완료다.

자동 테스트는 API 모의 응답·순수 함수·서버 렌더링 검증이다. 실제 사용자 조작과 요청·화면 전환이 이어지는 브라우저 검증은 별도로 남아 있다. 도구 오류는 `Importing module "node:process" is not allowed in node_repl`이며 앱 자체 오류로 판정한 것은 아니다.

사용자는 저장 실패 후 ‘다시 로그인’ 버튼으로 로그인하면 목록으로 이동하고 미저장 내용이 사라진 현상을 보고했다. 해당 흐름은 수정 전 코드와 일치해 이전 번들 실행 가능성을 안내하고 재빌드했다. 브라우저에 로드된 코드와 최신 코드로 재검증한 결과는 직접 확인하지 못했으므로 해결 확인으로 기록하지 않는다.

### 사용자 실제 화면 확인 결과

테스트 시작 전에 페이지를 새로고침해 최신 코드를 불러온다. 이후 세션 만료 복구를 확인하는 동안에는 새로고침하지 않는다. 기존 사용자 데이터 대신 테스트용 초안을 사용한다.

- [x] 공고 A·B에서 서로 다른 답변을 저장하고 목록 복귀·재진입 시 각각 유지되는지 확인한다. 저장한 초안의 수정 시각·목록 정렬도 확인한다. — 사용자 확인 완료(2026-11-02, “기본 저장 정상”). 같은 공고에서 기존 초안·답변이 열리는 것도 확인했다.
- [x] 같은 공고에서 기존 초안 ID를 여는지, 테스트용 초안 삭제 후 재작성하면 새 ID로 생성되는지 확인한다. — 기존 초안 재진입은 “기본 저장 정상”, 삭제 후 다른 ID·빈 답변으로 생성 및 저장·재조회는 “재작성 정상”으로 사용자 확인 완료(2026-11-02).
- [x] 편집 후 목록·탭 이동과 로그아웃의 폐기 확인을 취소해 입력이 유지되는지, 저장 성공 후에는 불필요한 확인 없이 이동하는지 확인한다. — 사용자 확인 완료(2026-11-02, “미저장 보호 정상”).
