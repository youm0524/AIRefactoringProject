# Issue #7 — 자기소개서 탭 구현

- Issue: https://github.com/youm0524/AIRefactoringProject/issues/7
- 목표: 여러 채용공고의 자기소개서를 목록에서 선택하고, 작성·저장·불러오기·삭제할 수 있게 한다.
- 진행 방식: 아래 순서로 한 단계씩 선택하고, 해당 단계의 상세 문서를 별도로 작성한 뒤 작업한다.

## 작업 순서

1. [x] **현재 코드 확인 및 기능 범위 결정**
   - 기존 작성·저장 방식을 확인하고, 화면 이동·최초 생성·로그인·기존 초안 처리 방식을 정한다.
   - 결정 내용: [1단계 문서](Issue-%237-Feature-Step-1.md)
2. [x] **화면 구성 정하기**
   - 목록에 표시할 정보, 상세 작성 화면, 목록과 상세 사이의 이동을 정한다.
   - 결정 내용: [2단계 문서](Issue-%237-Feature-Step-2.md)
3. [x] **데이터 구조 및 API 설계하기**
   - 사용자·공고·자기소개서·문항·답변의 관계와 생성·목록·상세·저장·삭제 API를 정한다.
   - 결정 내용: [3단계 문서](Issue-%237-Feature-Step-3.md)
4. [x] **DB 저장 기반 구현하기**
   - 마이그레이션, Entity, Repository를 추가하고 데이터 저장·조회를 확인한다.
   - 작업 문서: [4단계 문서](Issue-%237-Feature-Step-4.md)
5. [x] **자기소개서 생성·목록 조회 API 구현하기**
   - 최초 작성 데이터를 만드는 경로와 사용자별 목록 조회를 구현한다.
   - 작업 문서: [5단계 문서](Issue-%237-Feature-Step-5.md)
6. [ ] **자기소개서 상세 조회·수정·삭제 API 구현하기**
   - 선택한 자기소개서의 문항·답변 조회와 수정 내용 저장·본인 초안 삭제를 구현한다.
   - 작업 문서: [6단계 문서](Issue-%237-Feature-Step-6.md)
7. [ ] **목록 화면 구현 및 API 연결하기**
   - 자기소개서 탭에서 목록을 보여주고 선택한 항목의 상세 화면 연결과 삭제 확인·목록 갱신을 구현한다.
8. [ ] **상세 작성 화면 구현 및 저장 연결하기**
   - 문항·답변을 불러오고, 수정·저장·목록 복귀를 연결한다.
9. [ ] **전체 흐름 검증 및 문서 정리하기**
   - 공고별 데이터 구분, 저장 후 다시 불러오기, 삭제 후 재작성, 접근 권한, 오류 처리를 확인하고 관련 문서를 갱신한다.
