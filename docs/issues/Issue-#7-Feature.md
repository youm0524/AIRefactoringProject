## 변경 결과와 주요 결정

브라우저 로컬 저장 중심의 작성 화면을 로그인 사용자별 서버 초안으로 전환했다. 공고에서 작성을 시작하고, 자기소개서 목록에서 선택·편집·저장·재조회·삭제할 수 있다.

- 사용자·공고별 초안은 하나다. 같은 공고에서 다시 시작하면 기존 초안을 열고, 삭제 후 재작성하면 새 ID의 빈 초안을 만든다.
- 질문·순서·글자 제한을 초안 생성 시 복사해 보관한다. 이후 기업별 문항을 도입해도 기존 초안의 질문을 유지하기 위한 구조다. 현재는 지원 동기·직무 경험 두 문항, 각각 UTF-16 기준 700자다.
- 모든 자기소개서 API는 인증·소유권을 검사한다. 없는 초안과 타인 초안은 모두 404로 처리한다.
- 저장 실패 시 편집값을 유지하고, 미저장 이동에는 폐기 확인을 제공한다. 세션 만료 복구값은 사용자·초안별 메모리에 보관해 같은 계정만 복구하며 다른 계정에는 전달하지 않는다.
- 기존 로컬 초안은 사용자별로 구분되지 않았으므로 자동 이전하지 않고 원본을 보존했다. 신규 작성·저장은 서버를 사용한다.

## 최종 검증

2026-11-02 기준 결과다. 이후 변경 시 필요한 검증을 다시 실행한다.

| 검증 | 결과 |
| --- | --- |
| 프론트 자동 테스트·빌드 | 테스트 52개 및 프로덕션 빌드 통과 |
| 자기소개서 관련 ESLint | App, 목록·상세·작성 시작 화면, API, coverLetters 기능 폴더 통과 |
| 백엔드 전체 테스트 | 개발 DB와 분리된 MySQL에서 27개 통과, 실패·건너뜀 없음. 마이그레이션·제약조건·동시 생성/저장 포함 |
| 실제 API + MySQL·Redis | 공고별 저장·재조회·재작성, 기존 초안 불변, 미인증 401, 타인 접근 404, 잘못된 저장 400 및 데이터 보존 통과 |
| 사용자 브라우저 확인 | 목록·저장·재작성·미저장 보호·네트워크/서버 실패 재시도·세션 복구·계정 전환·느린 응답 차단·404·모바일·키보드·기존 기능 회귀 정상 |
| 전체 프론트 lint | 기존 채팅·기타 화면의 JSX 줄바꿈 오류 192건으로 실패. 별도 정리 필요 |

화면 검증은 사용자가 직접 확인했다. 에이전트의 직접 브라우저 검증이나 자동 브라우저 E2E를 수행한 결과는 아니다. 실제 API 검증에서는 새로 생성한 테스트 초안만 삭제하고 기존 목록 유지도 확인했다.

## 제한과 후속 작업

- 기업별 원본 문항 제공·편집, 공고 없는 자유 초안은 이번 범위에서 제외했다.
- 자동 저장·기존 로컬 초안 자동 이전·새로고침/브라우저 닫기 경고는 제공하지 않는다. 새로고침하면 메모리의 미저장 입력과 세션 복구값이 사라진다.
- 동시 저장은 마지막 성공한 저장을 적용한다. 충돌 감지·버전 관리는 후속 작업이다.
- 전체 lint 오류 정리와 브라우저 E2E 자동화가 남아 있다.

이 문서는 완료 시점의 요약이다. 현재 동작·계약은 위 영역별 안내 문서를 갱신하며 관리한다. 단계별 계획·진행 기록은 이 요약으로 통합했고, 이전 내용은 Git 이력에서 확인할 수 있다.
