# 기업 커뮤니티 구현 작업 T-04

> 전체 진행 상황: [기업 커뮤니티 구현 로드맵](./community-tasks.md)

## 작업 개요

- 선행 작업: T-02 참여 API, T-03 참여자 조회 API
- 상태: `DONE`
- 목표: 로그인 사용자가 참여 중인 기업 방에서 나가고, 같은 공고를 통해 재참여해 기존 대화를 다시 조회할 수 있게 한다.
- 제외 범위: 프론트엔드 확인창, 메시지 전송, WebSocket 연결 해제, Redis Pub/Sub

## 사용자가 확인할 결과

1. Swagger에서 `DELETE /api/community-rooms/{roomId}/membership`를 호출하면 `204 No Content`를 받는다.
2. 나간 방은 참여 방 목록에서 사라지고 메시지 조회는 `403 Forbidden`이 된다.
3. 같은 DELETE를 반복해도 `204 No Content`를 받는다.
4. 기존 참여 API로 재참여하면 같은 방이 목록에 다시 나타나고 기존 메시지를 조회할 수 있다.

## 실행 결과

- 변경 내용: 참여 관계를 잠근 뒤 삭제하는 멱등 나가기 API와 서비스 테스트를 추가했다.
- 검증 결과: 백엔드 테스트 11개 통과. 실제 API에서 나가기 후 목록 제외·메시지 조회 403, 반복·없는 방 나가기 204, 재참여 후 동일 방과 기존 메시지 2건, 새 참여 시각, 비인증 401을 확인했다. DB에는 참여 관계 1건과 기존 메시지 2건이 유지됐다.
- 남은 문제: MySQL 8.4에서 Flyway의 지원 범위 경고가 발생한다. 프론트엔드 확인창과 실시간 구독 제외는 후속 Task 범위다.
