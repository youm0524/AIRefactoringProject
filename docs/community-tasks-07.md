# 기업 커뮤니티 구현 작업 T-07

> 전체 진행 상황: [기업 커뮤니티 구현 로드맵](./community-tasks.md)

## 작업 개요

- 유형: `FEATURE`
- 선행 작업: T-02 참여, T-03 조회, T-04 나가기 API
- 상태: `DONE`
- 목표: 사용자가 로그인 후 독립 커뮤니티 화면으로 이동해 참여 방 목록과 기존 메시지를 보고, 공고를 통해 참여하거나 방에서 나갈 수 있게 한다.
- 제외 범위: 메시지 전송, WebSocket, Redis Pub/Sub, 모바일 화면 최적화와 시각적 마무리

## 사용자가 확인할 결과

1. 상단 커뮤니티 메뉴를 누르면 비로그인 사용자는 로그인 후 방이 선택되지 않은 커뮤니티 화면으로 이동한다.
2. 공고의 커뮤니티 버튼을 누르면 비로그인 사용자는 로그인 후 해당 기업 방에 참여하고 바로 선택된 화면으로 이동한다.
3. 커뮤니티 화면에서 참여 방 목록을 보고 방을 선택하면 최신 메시지를 조회할 수 있다.
4. 나가기를 확인하면 방이 목록에서 사라지고, 같은 공고로 다시 참여하면 기존 메시지를 다시 볼 수 있다.
5. API 실패 시 가짜 방이나 메시지를 표시하지 않고 오류 상태를 보여준다.

- [x] 공고 버튼의 참여·선택 흐름과 확인 후 나가기·재참여 흐름 연결

- [x] 상단 메뉴 로그인 흐름은 커뮤니티 화면으로 이동하되 방을 자동 선택하지 않는다.
- [x] 공고 버튼 로그인 흐름은 로그인 성공 후 한 번만 참여 API를 호출하고 반환된 방을 선택한다.
- [x] 로그인 실패 시 이동 의도를 유지하고 모달을 닫으면 폐기한다.
- [x] 참여 중인 방만 목록에 표시되고 방 선택 시 최신 메시지를 조회한다.
- [x] 나가기 전 확인을 표시하며 취소하면 유지되고 확정하면 목록과 선택 상태에서 제거된다.
- [x] 재참여하면 같은 방이 선택되고 기존 메시지가 다시 표시된다.
- [x] 인증 만료 시 저장 토큰을 제거하고 로그인 상태로 잘못 표시하지 않는다.
- [x] REST 실패 시 데모 데이터로 대체하거나 성공한 것처럼 표시하지 않는다.
- [x] 기존 채용공고·자기소개서 화면이 정상 동작하고 프론트엔드 테스트·변경 파일 린트·빌드가 통과한다.

## 실행 결과

- 변경 내용: REST API 모듈, 로그인 후 이동 의도, 독립 커뮤니티 화면, 참여·조회·나가기 흐름을 연결하고 기존 `JobChat`을 제거했다.
- 검증 결과: API 단위 테스트 포함 프론트엔드 테스트 3개와 빌드, 변경 파일 린트가 통과했다. 실제 백엔드에서 참여 방 1개와 메시지 3건을 조회한 뒤 나가기 204와 참여 방 0개 복구를 확인했고, 사용자 확인으로 화면 흐름을 완료했다.
- 남은 문제: 전체 `npm run lint`는 이번 변경과 무관한 기존 JSX 5개 파일의 포맷 오류 117건으로 실패한다.
