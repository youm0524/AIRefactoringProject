# WebSocket 실시간 메시지 송수신 T-05

> 전체 진행 상황: [기업 커뮤니티 구현 로드맵](./community-tasks.md)

## 작업 개요

- 관련 이슈: #15
- 유형: `FEATURE`
- 선행 작업: T-03 참여자 메시지 조회, T-04 방 나가기와 재참여, T-10 회사 관계 정규화
- 상태: `DONE`
- 목표: 로그인 사용자가 참여 중인 기업 방에서 메시지를 보내고, 같은 서버에 접속한 현재 참여자들이 저장된 메시지를 실시간으로 받는다.
- 제외 범위: Redis Pub/Sub 다중 서버 중계, 자동 재연결과 누락 복구, 모바일 화면 전환, 접근성·연결 상태 UI 마무리

## 사용자가 확인할 결과

1. 로그인한 두 브라우저에서 같은 기업 방에 참여하면 한 사용자가 보낸 메시지가 새로고침 없이 양쪽 화면에 표시된다.
2. 전송된 메시지는 DB에 먼저 저장되며 새로고침 후 REST 최신 메시지 조회에도 남아 있다.
3. 비로그인·세션 만료·미참여 사용자는 메시지를 보내거나 실시간 이벤트를 받을 수 없다.
4. 같은 `clientMessageId`를 반복 전송해도 메시지는 한 건만 저장되고 같은 저장 결과를 받는다.
5. 메시지 저장이 실패하면 성공한 것처럼 표시하거나 다른 사용자에게 전달하지 않고 입력 내용을 유지한다.

## 작업 내용

- [x] Spring WebSocket 의존성과 `/ws/community` 엔드포인트 및 허용 Origin 설정 추가
- [x] 연결 후 5초 이내 첫 `AUTH` 프레임으로 기존 opaque token을 검증하고 세션 만료 시각까지만 연결 유지
- [x] 인증된 사용자와 현재 서버의 WebSocket 연결을 관리하고 연결 종료 시 정리
- [x] `SEND_MESSAGE` JSON 프레임의 타입·방 ID·UUID·본문 1~120자 검증
- [x] 참여 관계를 잠근 상태에서 메시지를 저장하고 `(user_id, client_message_id)` 중복 전송을 멱등 처리
- [x] 트랜잭션 커밋 후 현재 서버에 연결된 해당 방 참여자에게 `MESSAGE_CREATED` 전달
- [x] 송신자에게 `SEND_RESULT`, 인증·권한·입력·저장 실패에는 안전한 `ERROR` 프레임 반환
- [x] 기존 커뮤니티 화면에 기본 메시지 입력·전송과 실시간 메시지 병합 연결
- [x] 서버 메시지 ID로 REST 조회·전송 결과·실시간 이벤트의 중복 표시 방지
- [x] 인증, 권한, 입력 검증, 중복 전송, 저장 후 전달과 나가기 동시성 테스트 추가
- [x] WebSocket 계약과 로컬 확인 방법을 백엔드·프론트 문서에 반영

## 예상 변경 범위

- Backend: WebSocket 설정·핸들러, 인증 세션 확인, 연결 관리, 메시지 저장·전달 서비스, DTO, Repository와 테스트
- Frontend: 커뮤니티 WebSocket 연결, 메시지 입력·전송, 실시간 이벤트 병합과 기본 오류 처리
- Database: 스키마 변경 없음. 기존 `client_message_id`와 유일 제약 사용
- 기타: WebSocket 통합 검증과 실행 문서

## 완료 조건

- [x] 연결 후 첫 프레임이 `AUTH`가 아니거나 5초 안에 인증하지 않으면 연결이 종료된다.
- [x] 잘못된 토큰과 만료 토큰은 인증되지 않으며 토큰과 내부 예외가 로그·응답에 노출되지 않는다.
- [x] 인증 성공 뒤 세션 TTL이 끝나면 연결이 종료된다.
- [x] 서버는 사용자 ID와 작성자명을 클라이언트 입력이 아니라 인증 세션에서 결정한다.
- [x] 현재 참여자만 메시지를 저장·전송·수신할 수 있고, 나가기 완료 후에는 전송과 수신이 차단된다.
- [x] 본문은 trim 후 1~120자이며 잘못된 UUID·방 ID·본문은 저장되지 않는다.
- [x] 메시지는 DB 커밋 이후에만 실시간 전달되고 저장 실패 시 이벤트가 전송되지 않는다.
- [x] 같은 사용자의 같은 `clientMessageId` 재전송은 기존 메시지를 반환하고 DB에 한 건만 남는다.
- [x] 서로 다른 사용자는 같은 `clientMessageId`를 독립적으로 사용할 수 있다.
- [x] 화면은 저장이 확인되기 전에 입력을 지우지 않고 서버 메시지 ID 기준으로 중복을 제거한다.
- [x] 기존 참여·목록·조회·나가기·재참여 기능이 그대로 동작한다.
- [x] 기존 관련 테스트와 새 테스트가 모두 통과한다.

## 실행 결과

- 변경 내용: opaque token 인증과 TTL 종료를 포함한 단일 서버 WebSocket 처리, 참여 관계 잠금 기반 멱등 저장, 참여자 실시간 전달, 기본 메시지 입력·병합 UI를 구현했다.
- 검증 결과: 백엔드 테스트, 프론트엔드 테스트·빌드와 변경 파일 린트가 통과했다. 임시 DB에서 Flyway 6개와 기존 커뮤니티 REST 회귀를 확인했고, 실제 WebSocket 두 연결의 수신·중복 전송·DB 한 건 저장·REST 재조회를 확인했다.
- 남은 문제: T-06에서 Redis Pub/Sub을 연결하기 전까지 실시간 이벤트는 같은 서버 인스턴스 안에서만 전달된다.
